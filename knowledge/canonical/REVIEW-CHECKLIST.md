# 精査チェックリスト（Canonical 採用基準）

収集・改変のたびに、このリストで判定する。基準自体も必要に応じて更新してよい。

## 1. 採用してよいか（Must）

- [ ] **主張が明確か** … 「いつ・何を選ぶべきか」が書かれている（単なる用語説明だけではない）
- [ ] **根拠があるか** … 一次情報、または自リポの該当箇所＋外部根拠、または広く合意された実務パターン
- [ ] **現行と矛盾しないか** … 2025–2026 の公式仕様（特に Effort / Thinking / モデル世代）と食い違っていない
- [ ] **再現可能か** … 同じ条件なら同じ推奨に至れる程度に条件が書かれている

## 2. 品質（Should）

- [ ] **失敗モードが書かれているか** … 選び間違えたときの典型的な失敗
- [ ] **代替案があるか** … 第一推奨が使えないときの次善
- [ ] **次元が明確か** … D1–D9 / X のどれに属するかがはっきりしている
- [ ] **過剰一般化していないか** … 特定製品・特定時期の話を普遍則のように書いていない

## 3. 不採用・保留にする場合

- 根拠が「自分の感覚だけ」で、一次情報とも自リポの構造的説明とも繋がっていない
- モデル世代依存の数値が古く、現行公式と衝突する
- 用語の定義だけで、判断（選ぶ／選ばない）に使えない
- 他次元と矛盾する推奨で、どちらを優先するかが書いていない

→ **不採用** か **要再検証**（ファイルに `status: needs-review` を付ける）とする。

## 4. ノートの推奨フォーマット

```markdown
# [指標名]

- status: canonical | needs-review
- dimensions: D6, X
- sources:
  - [一次情報 or 自リポパス]（要点）
  - …

## 判断の問い
（スキルやチェックリストが聞くべき質問）

## 推奨パターン
- 条件 A → 推奨 B（根拠）
- …

## よくある失敗
- …

## 代替・例外
- …
```

## 5. 収集時の運用

1. ソースを読む → 主張を抜き出す
2. 本チェックリストで判定
3. 通ったものだけ `canonical/dN-*/` にノート化
4. ソース一覧は各次元の `sources.md` にマッピングとして残す（不採用理由も短く残してよい）
5. `_index.md` の充足状況を更新する
