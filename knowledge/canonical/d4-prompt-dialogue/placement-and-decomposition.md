# プロンプトは痩せる（寿命と住所）

- status: canonical
- dimensions: D4, D3, D6

## 判断の問い

- この文は今回限りか、プロジェクトのあいだ残るか、案件をまたぐか
- 毎回同じ役割・禁止・形式を貼り直していないか
- 常駐に置きすぎて、今の対象と無関係な指示が同時に効いていないか

## 推奨パターン

よいプロンプトは関心の束である。束を寿命で分ける。プロンプトは消えない。**今回新しいことだけを運ぶ文に痩せる。**

七つの条件と主な住所:

| 条件 | 主な住所 |
| --- | --- |
| 役割 | Agent（今回限りならプロンプト） |
| 前提 | Memory（何が起きたか）/ Skills（何が真か） |
| 目的・禁止 | Doctrine |
| 入力 | MCP / RAG（毎回貼らない） |
| 処理と制約 | Doctrine（線）と Skills（手順） |
| 出力の形 | Skills（一回きりならプロンプト） |
| 例と確認 | Skills / Doctrine / ゲート |

注入のタイミング:

| 置き場 | いつ入るか | 向くもの |
| --- | --- | --- |
| 常駐（system / プロジェクト方針） | 毎ターン | 推測できないスタック、禁止、合格の線。短く |
| 条件付き | 今の対象に関係するとき | ファイル種別・チャネル種別の規則 |
| オンデマンド | そのタスクのとき | 手順書、テンプレ |
| 今回のユーザー発話 | そのターン | 今日の依頼だけ |

目的を毎回書いている → Doctrine が無いサイン。
入力を毎回貼っている → 取得経路が無いサイン。
特定対象にしか効かない規則が常駐にある → 条件付きへ移すサイン。

## よくある失敗

- 方針・手順・今回の依頼を一枚に全部書く
- 常駐を百科事典にする（Priority Saturation）
- 対話履歴の管理方針が無く、初期の system が中間に沈む

## 代替・例外

- ホストのファイル名（CLAUDE.md / rules / skills）は実装例。指標は「常駐 / 条件付き / オンデマンド / 今回」
