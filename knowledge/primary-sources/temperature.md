# Temperature — Primary Sources & Practical Guidelines (as of 2026-08)

## 基本的な意味

Temperature は次トークンの確率分布の鋭さを調整するパラメータ。
低いほど高確率トークンに集中（決定的）、高いほど多様・創造的になる。

## 用途別の目安（実務でよく使われる範囲）

| タスク | 推奨 Temperature | 理由 |
| --- | --- | --- |
| 構造化抽出・分類・ルーティング | 0.0〜0.2 | 決定性が最重要 |
| コード生成 | 0.0〜0.3 | 正確性・再現性 |
| 事実Q&A・RAG回答 | 0.1〜0.3 | ソースからの逸脱を抑える |
| 要約 | 0.3〜0.5 | 忠実さと読みやすさのバランス |
| 一般対話・ドキュメント生成 | 0.4〜0.7 | 自然さと一貫性 |
| マーケティングコピー・創作 | 0.7〜1.2 | 多様性・創造性 |
| アイデア出し・ブレインストーミング | 0.8〜1.3 | 意外性を許容 |

## プロバイダごとの注意点

- **OpenAI**: 0〜2、デフォルト 1.0 が多い。Reasoningモデルでは Temperature が制限される（固定値のみなど）場合がある。
- **Anthropic**: 0〜1、デフォルト 1.0。Extended thinking 利用時は temperature=1 が求められるケースがある。
- **Google Gemini**: 0〜2、デフォルト 1.0 付近。

## Reasoning / Thinking モデルとの関係

- Reasoningモデルでは Temperature の影響が小さくなる、またはAPI側で制限されることが多い。
- 思考の深さは **Reasoning Effort / thinkingLevel / effort** で制御するのが主軸になる。
- Temperature と Effort は別軸として扱う（揺らぎ vs 思考量）。

## 実務Tips

- Temperature と top_p を同時に極端に振らない（どちらか一方を主に調整するのが無難）。
- 本番では「決定性が必要な部分」と「創造性が必要な部分」でモデル呼び出しを分ける設計も有効。
- 評価セットで Temperature を変えたときの品質・一貫性を測ってから固定する。
