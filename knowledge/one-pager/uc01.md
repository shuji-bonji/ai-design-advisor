# 設計確認メモ

**対象**: 自社 EC のコンシューマ向け FAQ チャット。返品規約・配送・商品説明。在庫は社内 DB 参照。決済・返金実行はしない。
**前提**: データを社外モデルに渡してよい（PII は投入しない）。体感の対話が優先。合格線の数値目標は未確認。
**日付**: 2026-09-05
**位置づけ**: 打ち合わせ用。決定ではない。確認してほしい論点。
**元**: [`../use-cases/uc01-consumer-faq.md`](../use-cases/uc01-consumer-faq.md)。判断は変えていない。

## 決まっていること

- 決済・返金は実行しない
- PII はモデルに投入しない
- データを社外モデルに渡してよい
- 在庫は社内 DB を参照する

## 決まっていないこと

- 体感の上限は「最初の字」か「最後まで」か
- 社外モデルに渡してよいデータの範囲（PII 以外）
- 在庫 API は読み取り専用か
- 合格の線は数字か、人が見る作業か

## ベンダーに確認すること

- 規約・商品は検索で足すか。口調のために学習するなら、要否は先か
- 在庫・注文を検索索引の第一手段にしていないか
- 答えられないときの経路はあるか
- 検索の当たりと回答の当たりを分けて測るか
- 自律的な繰り返しや決済実行を初手に載せていないか
- 製品一枚で入力の改ざん対策が済んだとしていないか
