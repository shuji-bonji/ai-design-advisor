# 設計判断レポート: UC17 閉域上の共同利用

**対象**: 閉域網上の生成AI を複数組織が共同利用する。主用途は文案作成・議事録要約。
**前提**: データは外に出せない。組織ごとに知識が違う。基幹への書き込みは無い想定。合格線は未確認。
**日付**: 2026-08-31
**型**: スキル完全出力（canonical 検証用）
**元**: [memo-e-closed-network-multitenant.md](./memo-e-closed-network-multitenant.md)

### 推奨構成（要約）

- モデル: 閉域内の SLM / 小さい LLM。クラウド比較より D1 が勝つ
- パラメータ: Temperature は文案だけ少し上げてよい。Effort は上げない
- 知識: 共有と組織固有を分ける。組織固有はテナント分離
- 実行系: 文案・要約なら段 0–1。エージェントにしない
- Fine-tune: しない
- 権限: 組織間の ACL。閉域を安全と見ない
- 測り方: 越権の有無。導入率は合格線にしない

### 詳細

- **推奨**: 文案・要約なら段を上げない。分離はインデックスと会話の両方。閉域を壁にしない。
- **なぜ**: UC03 の多テナント版。ベクトル弱点はテナント越権（threat-landscape）。
- **代替**: 組織ごとにインスタンスを分ける（共有コストは上がる）。
- **禁止**: 「閉域だから安全」、共有 RAG に例規を混ぜる、文案用途に Multi-agent。

### ベンダーに渡す文

- やること: テナント分離、共有知識の目録、注入面の説明
- やらないこと: 閉域を安全証明にする、組織跡の共有
