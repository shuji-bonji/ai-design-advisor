# 設計判断レポート: UC03 社内ナレッジ RAG

**対象**: 社員向けの社内文書 Q&A。規程・手順書・既往 QA。根拠提示が必須。書き込みは無い。
**前提**: 利用者は社員。文書に ACL がある。社外モデル可否は未確認。合格線の数値は未確認。
**日付**: 2026-09-01
**型**: スキル完全出力（canonical 検証用）
**位置づけ**: 確認論点。決定ではない。一貫性チェックであり、成否の検証ではない。

### 決まっていないこと

- 社外モデルに渡してよいか
- 部署マスタ・人事が検索対象か（関係ならツール）
- 合格線の数値

### ベンダーに確認してほしい論点

- 検索前に ACL をかけているか
- 権限の違う文書を同じ索引に乗せていないか
- 検索と回答を分けて測るか
- 取れないとき答えない定型があるか
- FAQ を重みへ焼いていないか
- 検索を自律ループにしていないか

### いま言えること

- モデル: 定型は中〜小。長文の整理だけ大きい
- パラメータ: Temperature 低め。Effort は最小
- 知識: Hybrid + Rerank。権限なし文書を混ぜない。マスタは embedding しない
- 実行系: 一回の検索 + 回答 + 引用。Agentic RAG にしない
- Fine-tune: しない
- 権限: 検索に ACL。根拠が無ければ答えない
- 測り方: 検索と回答を分ける

### 詳細

- **推奨**: 一回の検索 + 回答 + 引用。権限の違うコーパスを同じインデックスに乗せない。
- **なぜ**: 出典と更新が要件。FT も Agentic RAG も先に壊れる。
- **代替**: 検索が親を汚すなら検索だけ Sub-agent。全件を自律ループにしない。
- **禁止**: FAQ を重みへ焼く、権限なし文書の混入、マスタを embedding だけで解く。
