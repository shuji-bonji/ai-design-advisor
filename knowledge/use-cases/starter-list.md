# 代表ユースケース スターターリスト

実務でよく見られるパターンをベースに、初期の洗い出しを行う。
各項目は後で詳細化する。

## 1. コンシューマ向け自社サービスチャットボット
- 典型制約: レイテンシ、コスト、ブランドトーン、ガードレール、HITL
- 主な判断ポイント: モデルクラス、Temperature、ガードレールの強さ、評価方法、会話履歴の扱い
- よくある失敗: トーンのブレ、ハルシネーションによるブランド毀損、想定外のコスト増

## 2. 社内ナレッジ活用（RAG）
- 典型制約: 知識の鮮度、アクセス権限、回答の根拠提示
- 主な判断ポイント: チャンキング戦略、Embedding選定、VectorDB、グラウンディング、評価（LLM-as-a-Judge）
- よくある失敗: チャンク設計の甘さ、検索精度不足、古い情報の混入

## 3. コンテンツ生成・創作支援（コピー、アイデア、ドキュメント）
- 典型制約: 創造性と一貫性のバランス、著作権・トーン
- 主な判断ポイント: Temperature帯、Few-shot / 例示の使い方、人間レビューの位置づけ

## 4. 分類・抽出・定型処理
- 典型制約: 高い決定性、スループット、コスト
- 主な判断ポイント: 低Temperature、SLMの可否、構造化出力、評価の自動化

## 5. エージェント的業務自動化（Tool Calling）
- 典型制約: ツールの信頼性、エラーハンドリング、HITLの粒度
- 主な判断ポイント: Single vs Multi-Agent、Reasoning Effort、Tool設計、ループ制御

## 6. オンデバイス / 高プライバシー
- 典型制約: 端末性能、モデルサイズ、オフライン動作
- 主な判断ポイント: SLM選定、量子化、コンテキスト管理、機能の絞り込み

## 7. 高リスク・高説明責任領域（医療・金融・法務寄りなど）
- 典型制約: 正確性、監査可能性、HITL必須
- 主な判断ポイント: Reasoning Modelの活用、強いガードレール、ログ・根拠の保存、人間最終判断
