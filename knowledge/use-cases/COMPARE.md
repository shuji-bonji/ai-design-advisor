## 見る三点

スキルが素のモデルより上なのは、この三点だけ、という前提で見る。

1. 案件を踊いで枠が同じか（D1–D9 + X、確度）
2. 足りない入力を発明せず `情報不足` と言うか
3. 古い数値・製品名・条番号を引かないか

見ないもの: 文章の上手さ、構成図の量、特定スタックの新しさ。

## 入力

同じ文を両方に渡す。足さない。

- 対象と前提は既存 UC の先頭（未確認は未確認のまま）
- 最初の一本は [uc01-consumer-faq.md](./uc01-consumer-faq.md) の「対象」「前提」だけ
- 次点は制約が勝つ UC06（外出禁止）、UC18（待たせられない）、UC20（FT する側）
- 貼り用に切った文: [COMPARE-PROMPTS.md](./COMPARE-PROMPTS.md)

プロンプト例（素のモデル）:

```
次の生成AIシステムの設計を提案してください。
分からないことは推測で埋めず、決まっていないと書いてください。

対象: …
前提: …
```

スキル側は `skills/ai-design-advisor/SKILL.md` の完全出力。

## 記録の型

結果はここに貼らず、Issue かメモへ。行は次で足りる。

| 入力 | 枠が同じか | 発明したか | 腐る数字を引いたか | 一言 |
| --- | --- | --- | --- | --- |
| UC01 対象+前提 | | | | |

「発明したか」は、入力に無いレイテンシ数値・製品名・法令名・段の断定を数える。

## やらないこと

- 比較のために新しい UC を作らない
- 素の出力を正本やスキル文に折り込まない
- Web を先に作らない（一枚は比較のあと）
