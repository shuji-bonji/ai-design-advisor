# 設計判断レポート: UC15 融資票議ドラフトと後続連鎖

**対象**: 行内の構造化データと票議添付・事務マニュアルから担当者意見のドラフトを作り、契約・実行事務・モニタリングへ連ねる。
**前提**: 担当者が使う。外販予定あり。データ外出は未確認。承認の所在は未確認。意見の質の線は未確認。

**型**: スキル完全出力（canonical 検証用）
**元**: [memo-c-loan-review-draft.md](./memo-c-loan-review-draft.md)

### 推奨構成（要約）

- モデル: 論点整理は LLM。外出不可なら D1 が勝つ
- パラメータ: Temperature 低め。Effort は論点整理だけ
- 知識: RAG + Grounding。過去票議は偏りを疑う。何を入れないかを先に決める
- 実行系: 3 プロセスを 1 ループにしない。承認の位置で切る
- Fine-tune: しない
- 権限: permission。「意見」でなく「論点と根拠」で止める
- 測り方: 引用と跡。削減時間を質の代わりにしない

### 詳細

- **推奨**: 「意見」ではなく論点と引用。決裁は人。3 プロセスは承認で切る。
- **なぜ**: 判定を下流が信じると取り消せない（permission-vs-authority）。過去票議をそのまま知識にすると偏りを継承する。
- **代替**: 第 1 プロセスだけ下書き。後続は別システム。
- **禁止**: 自動決裁、過去仲裁の全文 FT、自組織データの外販還流を口頭で済ませる。

### ベンダーに渡す文

- やること: 引用必須、プロセス両端の承認、学習利用と帰属を契約に書く、知識から外す一覧
- やらないこと: 意見の自動確定、黒箱オーケストレータ、法令名の転記

### 追加確認

- データを外に出せるか
- 承認者は担当者か役割か
- 外販時に自組織データが還流するか
