# 設計判断レポート: UC13 診察会話からのカルテ下書き

**対象**: 診察室の会話音声を文字化し、定型書式のカルテ下書きを電子カルテへ渡す。
**前提**: 使用者は医師。データは外に出せない（院内完結）。起案者と承認者が同一人。合格線は未確認。
**日付**: 2026-09-01
**型**: スキル完全出力（canonical 検証用）
**元**: [memo-a-clinical-note-draft.md](./memo-a-clinical-note-draft.md)
**位置づけ**: 確認論点。決定ではない。一貫性チェックであり、成否の検証ではない。

### 決まっていないこと

- 患者同意と第三者発話の扱い
- 音声・文字起案の保持期限
- 起案者＝承認者のまま運用するか
- 合格線（時間短縮は品質の代わりにしない）

### ベンダーに確認してほしい論点

- 院内完結か。社外 API 前提になっていないか
- ASR 誤りと生成誤りを分けて測るか
- 確定 UI があるか。空欄を埋めないか
- 下書きを自動確定していないか
- 時間短縮率を仕様化していないか

### いま言えること

- モデル: 音声は分離して文字化。下書きは院内の SLM / 小さい LLM
- パラメータ: Temperature 低め。Effort は上げない
- 知識: 書式と院内規約は Skill / 定型。最新 RAG は不要
- 実行系: 書き込み前に医師確認。Multi-agent にしない
- Fine-tune: しない
- 権限: permission。起案＝承認なので HITL は「別人の壁」ではない
- 測り方: ASR 誤りと生成誤りを分ける。時間短縮だけを合格線にしない

### 詳細

- **推奨**: ASR と下書き生成を分ける。確定は医師。HITL は「別役割の壁」ではなく「確定手順と跡」。
- **なぜ**: 出せないなら D1 が勝つ。音声は注入面。自己承認は permission-vs-authority の失敗例に近い。
- **代替**: 文字化だけ人が書く。生成を載せない。
- **禁止**: クラウド LLM 前提、下書きの自動確定、生音声の無限保管、時間短縮率を品質の代わりにする。
