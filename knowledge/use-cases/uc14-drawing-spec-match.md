# 設計判断レポート: UC14 図面・仕様書の項目照合

**対象**: 複数 PDF 図面・技術仕様書から項目を抽出し、文書間で一致するかを照合して一覧で返す。
**前提**: 読み取りのみ。知識は入力そのもの（RAG しない）。データを外に出せるかは未確認。合格線は未確認。
**日付**: 2026-09-01
**型**: スキル完全出力（canonical 検証用）
**元**: [memo-b-drawing-spec-match.md](./memo-b-drawing-spec-match.md)
**位置づけ**: 確認論点。決定ではない。一貫性チェックであり、成否の検証ではない。

### 決まっていないこと

- データを外に出せるか
- 見逃しと誤検出のどちらを先に見るか
- テキスト化できない図面の割合
- 合格線

### ベンダーに確認してほしい論点

- 未取得を別状態で返すか。取れなかった項目を一致としていないか
- 一致判定をコードにしているか。LLM に任せていないか
- 抽出と照合を分けて測るか
- 取れない図面を落としていないか

### いま言えること

- モデル: 抽出は SLM / 低 Temperature。図面が画像なら Multimodal 入力
- パラメータ: Temperature 0 寄り。Effort は上げない
- 知識: RAG しない。入力文書そのもの
- 実行系: 抽出だけ生成。一致判定は決定的コード
- Fine-tune: しない
- 権限: 読み取り。書き込みなし
- 測り方: 抽出成功と一致判定を分ける。取れない項目を一致にしない

### 詳細

- **推奨**: 生成は抽出まで。一致はコード。残る項目は未取得のまま一覧に出す。
- **なぜ**: 正解が決定できる仕事に自律ループを足さない。取れないのに一致と言わせない。
- **代替**: 人が項目を指し、ツールは検索だけ。
- **禁止**: 未取得を一致とする、Agentic RAG、削減率を見逃し率の代わりにする。
