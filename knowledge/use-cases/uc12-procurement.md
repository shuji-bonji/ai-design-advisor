# 設計判断レポート: UC12 調達・ベンダー選定

**対象**: 業務側が社内 FAQ + 社内 RAG をベンダーに依頼する前の仕様整理。製品ではなく、契約と責務の分割が本件。
**前提**: 事業利用者は自社。開発・提供はベンダー候補。適用法規名は未確認。
**日付**: 2026-09-01
**型**: スキル完全出力（canonical 検証用）
**位置づけ**: 確認論点。決定ではない。一貫性チェックであり、成否の検証ではない。

### 決まっていないこと

- 自社が事業利用者のままか、提供者にもなるか
- データをベンダー機器に渡してよいか
- 適用法規の名前

### ベンダーに確認してほしい論点

- 開発者 / 提供者 / 事業利用者を契約で空にしていないか
- 提示の所有を委託先に書くか
- ACL と引用を仕様項にしているか
- 検索と回答の別評価を仕様に書くか
- 手法名から入る提案になっていないか
- NIST / AISI 表を採点表にしていないか

### いま言えること

- モデル: 定型 FAQ は小さい側（UC01 寄り）
- パラメータ: Temperature 低め
- 知識: RAG + 引用。FT しない
- 実行系: エージェント化を仕様に書かない
- Fine-tune: しない
- 権限: 主体を契約に書く。NIST / AISI 表は採点にしない
- 測り方: 検索と回答を分ける項を仕様へ

### 次元別

| 次元 | 推奨 | 根拠 | 確度 |
| --- | --- | --- | --- |
| D1 | 定型は小さい側。社外不可なら D1 が勝つ | D1-001 | 条件付き |
| D2 | Temperature 低め。Effort 最小 | D2-001 | 確定 |
| D3 | 常駐は短く | D3-001 | 確定 |
| D4 | 提示の所有は委託先に書く | D4-002 | 確定 |
| D5 | Hybrid + Rerank、ACL、引用を仕様項にする | D5-001 | 確定 |
| D6 | 検索 + 回答までを仕様上限にする | D6-004 | 確定 |
| D7 | しない。手法名から入らせない | D7-003 | 確定 |
| D8 | 開発者 / 提供者 / 事業利用者を契約で空にしない | D8-002 / D8-003 | 条件付き |
| D9 | 検索と回答の別評価を置く | D9-004 | 条件付き |
| X | キャッシュと縮退を仕様に書く | X-001 | 確定 |

D1 が条件付きなのは、データをベンダー機器に渡してよいかが未確認だから。D8 は、法規名とガイドライン表を確定推奨にしないから。D9 は、自社が事業利用者のままか提供者にもなるかで、評価を誰の責務として仕様に書くかが変わるから。

### 詳細

- **推奨**: UC01 + UC03 の構成を仕様に落とす。責務の主体を空にしない。
- **なぜ**: 「ベンダーがやる」だけだと主体が空く（legal-actors）。
- **代替**: DS-920 の項を仕様の目次にしてよい。採点表にしない。
- **禁止**: NIST / AISI 表の転記、LoRA から入る提案、ガイドライン全文の契約化。
