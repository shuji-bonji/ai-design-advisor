## 判断の問い

- 最適化したいのは **品質のゆれ** か **トークンの席** か
- 長いのは常駐か、今回の入力か、出力か
- その長さは毎回払っているか、キャッシュで済むか

## 推奨パターン

二列に分ける。混ぜると「短くしたら壊れた」が起きる。

### A. 品質（ゆれを止める）

| 手法 | 使うとき | しないとき |
| --- | --- | --- |
| 軸を書く（役割・形式・合格線） | セッションごとに飛ぶ | 「ちゃんと」で済ませる |
| 常駐 / 条件付き / オンデマンド / 今回 | 一枚が肥大した | 全部を system に乗せる |
| Zero-shot | 一般知識で足り、例が足しにならない | 書式が固いのに例を貼らない |
| Few-shot | 書式・ラベルが決まっている | 例だけ表層を変えて「効かない」と言う |
| 手順を踏ませる（CoT 相当） | 多段が品質に効く、Reasoning モデルではない | Reasoning + 「考えろ」（D2） |
| 問題を小さく割る | 条件分岐が多い一発 | 単発で足りるのに分割する |
| 構造化出力 | 下流が機械読みする | 人が読む文にスキーマを強制する |

### B. トークン（席を止める）

消費 = 入力トークン × 回数 + 出力トークン × 回数。

| 手法 | 何を減らす | 条件 |
| --- | --- | --- |
| 常駐を痩せる | 毎ターンの固定費 | 禁止と合格線だけ残す |
| 入力を貼らない | RAG / MCP 全文 | 当たった少数 + 要約（D5） |
| 出力上限 | decode 費 | ハード上限と「短く」の両方 |
| 短い回答方針 | 出力 | 人が読む文は 2–4 文。分類は鍵 |
| 接頭辞キャッシュ | 繰り返す system / ツール定義 | 接頭辞が安定なときだけ |
| 関連部分だけ渡す | 常駐の再処理 | 非信頼入力だけ検査する |
| 無関連入力を止める | 貼り付け・ジャンク | フィルタはプロンプトの外（D8） |

「別 LLM で短くする」は短縮後を評価セットで見てから。短縮が軸を落とす。

### 症状 → 手法

| 症状 | 列 | 手法 |
| --- | --- | --- |
| 回ごとに書式が違う | A | 軸を書く |
| 常駐が長く今回の依頼が沈む | A | 住所を分ける |
| 例を 10 個乗せて高い | B | 例を減らし、書式だけ残す |
| 入力が出力の数倍 | B | 常駐削減 + RAG を貼らない |
| 出力が止まらない | B | max tokens + 短い方針 |
| 同じ system を毎回全額払っている | B | 接頭辞キャッシュ |

### 手順（現場）

1. 常駐のトークン数を知る
2. 軸が空なら A が先
3. 軸が指定済みで席が支配的なら B
4. 変更は 1 箇づつ。回帰する（C09）
5. 繰り返す接頭辞が長いならキャッシュ

コンシューマ向け: 常駐は方針 + 禁止 + 形式。FAQ は例より検索。出力は 2–4 文。

スキルの根拠列: 品質ならこのファイル + writing / placement。トークンならこのファイル + cost-decomposition。

## よくある失敗

- 軸を書かずに文章を削る
- Few-shot を 10 件乗せて固定費が肥大する
- Reasoning モデルに CoT を足す
- キャッシュさせたいのに常駐を毎回微調整する
- TTL や最小トークン数を他社に転記する
