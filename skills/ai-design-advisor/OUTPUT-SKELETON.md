# 出力スケルトン（スキルとチェックリストの契約）

スキル版の最終成果はこの型に落とす。
打ち合わせに持って行くときは、同じ報告を HTML にしない。[持って行ける一枚](#持って行ける一枚)。

## 最小出力（対話の途中）

要件がまだ薄いときは「決まっていないこと」と確認論点だけ出してよい。次元表は空欄を残す。情報不足の羅列を失敗に見せない。

## 完全出力（判断として渡すとき）

1. 対象と前提
2. 位置づけ（確認論点。決定ではない。一貫性であり成否検証ではない）
3. 決まっていないこと（情報不足を先に）
4. ベンダーに確認してほしい論点（指示ではない）
5. いま言えること（箇条書き、7行以内）
6. 次元表（D1–D9 + X、確度つき）
7. 詳細（推奨 / なぜ / 代替 / 禁止）

テンプレート本文は [SKILL.md](./SKILL.md) の「出力フォーマット」。

## 次元表の書き方

| 列 | 書くもの |
| --- | --- |
| 次元 | D1–D9 + X |
| 推奨 | 選ぶ判断。canonical に無いことは書かない |
| 根拠 | canonical の**ノート ID**（`D5-001`）。複数なら ` / ` で並べる。ファイル名や見出しは書かない |
| 確度 | 確定 / 条件付き / 情報不足 |

対応表は `canonical/_ids.md`。

## 確度の使い方

| 確度 | 使うとき | 根拠の欄 |
| --- | --- | --- |
| 確定 | canonical があり、制約と衝突しない | ID が 1 つ以上。**空にできない** |
| 条件付き | 「データが出せないなら SLM」のように分岐がある | ID を書く。表の直後に条件を一文 |
| 情報不足 | D7 手法、入力欠損、ノート未精査 | 空でよい。表の直後に何が足りないかを一文 |

該当する ID が無いのに文章が書けてしまう場合は、**確度を「情報不足」にする**。文章が書けることは根拠ではない。

## 出したあとに検算する

リポジトリのルートで次を実行する。

```sh
node scripts/check-output.mjs <出力した .md>
```

| 判定 | 何を見ているか | 終了コード |
| --- | --- | --- |
| エラー | 存在しない根拠 ID、語彙外の確度、根拠のない「確定」 | 1 |
| 警告 | 「条件付き」「情報不足」なのに表の直後に理由が無い | 0（`--strict` で 1） |
| 判定不能 | canonical を読めなかった | 2 |

終了コード 2 を 0 と分けているのは、**測れなかったことを「一致」に混ぜない**ためである。

リポジトリの `knowledge/use-cases/` は `--strict` で警告 0 を保つ。既定は `--strict` にしない。生成した直後の出力は理由の一文がまだ無いことがあり、そこで止めると書き足す前に落ちるためである。

## ベンダー文の書き方

- 「段 2–3」「焼かない」「確度: 条件付き」は内部語彙。渡す文には使わない
- 「これを実装せよ」ではなく「これを確認してほしい」
- やらないことの候補は、封じるためではなく、過副構成を疑うため

## 持って行ける一枚

打ち合わせ用に求められたら、完全出力のあと三段だけ落とす。一枚から推奨を作らない。

- 「決まっていること」は入力で確定した制約。「いま言えること」をここへ移さない
- 次元表・確度・内部語彙は載せない
- 見本はリポジトリの `knowledge/one-pager/`（スキルは読まない）

```markdown
# 設計確認メモ

**対象**: …
**前提**: …（未確認は未確認）
**日付**: YYYY-MM-DD
**位置づけ**: 打ち合わせ用。決定ではない。確認してほしい論点。

## 決まっていること

- …（入力で確定した制約）

## 決まっていないこと

- …（情報不足。発明しない）

## ベンダーに確認すること

- …（問い。指示として読まない）
```

## 例（短い）

対象: 自社ECのコンシューマ向けFAQチャット。返品・在庫は社内DB。決済はしない。

決まっていないことの例:
- 体感の上限（最初の字か、最後までか）
- 社外モデルに渡してよいデータの範囲
- 在庫 API が読み取り専用か

確認論点の例:
- 規約は検索で足すか、口調安定のために学習するか（後者は要否が先）
- 在庫・注文を embedding の第一手段にしていないか
- 答えられないときの経路はあるか

いま言えることの例:
- モデル: 通常は中〜小、難しい問い合わせだけ大きい / Reasoning
- パラメータ: Temperature 低め、Effort は最小から
- 知識: RAG（商品・規約）。Memory は急がない
- 実行系: Tool は在庫参照まで。書き込みなし。Agent にしない
- Fine-tune: しない
- 権限: 参照のみ。個人情報はログに残さない
- 測り方: 検索と回答を分けて測る。答えられない経路を置く

D7 手法を聞かれたら情報不足、と返す。
