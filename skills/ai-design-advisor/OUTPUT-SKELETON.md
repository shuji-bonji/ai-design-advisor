# 出力スケルトン（スキルとチェックリストの契約）

スキル版も Web 版も、最終成果はこの型に落とす。

## 最小出力（対話の途中）

要件がまだ薄いときは、要約と「追加で確認」だけ出してよい。次元表は空欄を残す。

## 完全出力（判断として渡すとき）

1. 対象と前提
2. 推奨構成の箇条書き（7行以内）
3. 次元表（D1–D9 + X、確度つき）
4. 詳細（推奨 / なぜ / 代替 / 禁止）
5. ベンダー向けのやること・やらないこと
6. 追加確認

テンプレート本文は [SKILL.md](./SKILL.md) の「出力フォーマット」。

## 確度の使い方

| 確度 | 使うとき |
| --- | --- |
| 確定 | canonical があり、制約と衝突しない |
| 条件付き | 「データが出せないなら SLM」のように分岐がある |
| 情報不足 | D7 手法、入力欠損、ノート未精査 |

## 例（短い）

対象: 自社ECのコンシューマ向けFAQチャット。返品・在庫は社内DB。決済はしない。

要約例:
- モデル: 通常は中〜小、難しい問い合わせだけ大きい / Reasoning
- パラメータ: Temperature 低め、Effort は最小から
- 知識: RAG（商品・規約）。Memory は急がない
- 実行系: Tool は在庫参照まで。書き込みなし。Agent にしない
- Fine-tune: しない
- 権限: 参照のみ。個人情報はログに残さない
- 測り方: 検索と回答を分けて測る。答えられない経路を置く

D7 手法を聞かれたら情報不足、と返す。
